- **Evidence basis:** source-and-discussion

- **Source:** https://developers.openai.com/api/docs/guides/decisions

The API offers a cheap, structured alternative to prompting general LLMs for binary or categorical classification—paying only for input tokens—but its value depends on whether probability calibration is trustworthy enough for production routing decisions. The emergence of specialized competitors like Jev forces a direct accuracy-vs-cost-vs-convenience tradeoff that developers now have to evaluate.

**Linked source:** The OpenAI Decisions API documentation describes a structured classification endpoint at /v1/decisions that accepts typed 'questions' (predicate, choice, or score) and returns probability distributions rather than free-form text, using the gpt-6-luna model at $0.10 per 1M input tokens with no output-token charges. The source states the API supports Zero Data Retention and HIPAA use for eligible customers, and recommends using labeled application examples to set thresholds for routing, filtering, or review.

**HN discussion:** Commenters are primarily focused on whether OpenAI's general-purpose model can match specialized decision models like Jev in accuracy and cost, and whether this release was a rushed competitive response. One commenter ran preliminary evals comparing the Decisions API against Jev and Mercury Decide, reporting higher latency and less confidence on ambiguous tasks.

### [OpenTPU – An open-source AI accelerator, developed by AI](https://news.ycombinator.com/item?id=49980715)

- **HN engagement:** 296 points, 346 comments
- **Primary topic:** OpenTPU: an open-source AI accelerator designed by AI agents, running on an FPGA
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://github.com/FeSens/openTPU

OpenTPU demonstrates a full hardware-to-inference stack—RTL through compiler—built by AI agents and running real model weights on commodity FPGA hardware, making it a rare open reference for understanding AI accelerator internals end to end. The recursive self-improvement angle also raises concrete questions about how far AI-driven hardware design can go without human intervention.

**Linked source:** The openTPU GitHub repository presents an open-source AI accelerator—including RTL, ISA, simulator, compiler, and profiler—developed by AI agents, targeting a Xilinx Kintex-7 PCIe card and capable of running ten modern models such as Qwen3, LFM2.5, and Gemma 4, with decode throughput ranging from ~4 to 85 tok/s depending on model and quantization. The project claims decode performance is currently DRAM-bound at 82–94% of DDR3-1066 peak, and active work focuses on the final DRAM efficiency gains, timing margin, and prefill speed.

**HN discussion:** HN commenters responded with a mix of curiosity about AI-generated hardware design and humor about recursive self-improvement tropes; one commenter speculated that a SOTA model has been able to produce a working accelerator since around December and asked whether AI could design model architectures optimized for reconfigurable FPGA fabric. The submission author noted the project started at a few tokens per second and reached 80+ tok/s on smaller models through a recursive self-improvement loop.
