### [Sharing AI progress in mathematics](https://news.ycombinator.com/item?id=49984923)

- **Evidence basis:** source-and-discussion

- **Source:** https://openai.com/index/sharing-ai-progress-in-mathematics/

The release raises immediate practical and epistemic questions about how AI-generated mathematical proofs can be trusted, given that Lean formalizations are only partial and the underlying model is not yet publicly released. The disclosure methodology—compute estimates, reasoning summaries, and a GitHub repository—sets a precedent for how AI research labs might responsibly share frontier scientific results.

**Linked source:** OpenAI's page announces a GitHub repository release of new mathematical results produced by an internal frontier model, including Lean formalizations of many proofs, reasoning summaries, compute estimates (averaging roughly three hours of ChatGPT Pro thinking per result), and statistics on attempted problems. The release was developed in consultation with an Advisory Group on Mathematics and Artificial Intelligence at the Institute for Advanced Study, with a commitment to improve citation quality and exposition in future releases.

**HN discussion:** Commenters reacted with a mix of mathematical excitement, personal emotion, and existential unease, focusing on specific high-profile results such as the claimed proof of the Unique Games Conjecture and progress on Millennium Prize problems. One commenter expressed personal grief over a decades-long problem (Barnette's Conjecture) appearing in the release, while another noted that several results address areas where physics and math communities already had strong expectations but lacked rigorous proofs.

### [Decisions API is in public beta](https://news.ycombinator.com/item?id=49984025)

- **Primary topic:** OpenAI Decisions API public beta for structured boolean/classification model outputs
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://developers.openai.com/api/docs/guides/decisions

The API offers a cost structure where only input tokens are billed and classification outputs consume zero output tokens, which could substantially reduce costs for high-volume routing and filtering workloads. However, developers are already comparing it unfavorably on latency and calibration quality against established competitors like Jev.

**Linked source:** The OpenAI Decisions API documentation describes an endpoint that accepts an input and an array of typed questions (predicate, choice, or score) and returns probability distributions rather than free-text—priced at $0.10 per 1M input tokens with no output-token charges, and currently limited to the gpt-6-luna model. The source also notes support for Zero Data Retention, HIPAA eligibility, and voice-control integration via the Live API.

**HN discussion:** Commenters frame the Decisions API as a direct competitive reaction to Jev and similar fast, cheap classification models, with one commenter benchmarking it as slower than Jev and comparable in latency to Mercury Decide at roughly 346ms p50 and 860ms p95. One commenter raises a deeper concern: making decision probabilities explicitly visible may paradoxically erode business confidence in AI-assisted decisions.

- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://strandsagents.com/blog/introducing-strands-decider/

A sub-2B decision model with a pointer head rather than a text-generation head offers a path to placing structured binary checks in latency-sensitive agent pipelines—such as before-tool-call interventions—where full LLM inference is impractical. The open-source release of weights, training data, and code lowers the barrier to experimentation and customization.

**Linked source:** The Strands blog post introduces Decider 2B, an open-source 2-billion-parameter model that replaces a text-generation head with a dedicated pointer head to produce fast, structured binary decisions (called 'noul' choices); it is designed to sit inside agent intervention handlers—such as a before_tool_call hook—to gate tool calls cheaply where a full LLM call would be too slow or expensive.

**HN discussion:** Commenters are broadly positive about the blog post's clarity, but the technical conversation splits between curiosity about API naming conventions (the 'noul' binary-choice type) and practical deployment concerns around running small micromodels on NPUs rather than CPUs. One commenter also noted the pragmatic architectural rationale of swapping the text-generation head for a pointer head.

### [OpenTPU – An open-source AI accelerator, developed by AI](https://news.ycombinator.com/item?id=49980715)

- **HN engagement:** 292 points, 342 comments
- **Primary topic:** OpenTPU: an open-source AI accelerator designed by AI agents, running on an FPGA
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://github.com/FeSens/openTPU

OpenTPU is a rare end-to-end open-source example of AI agents producing hardware—RTL through compiler—that runs real inference workloads on accessible FPGA hardware. It also serves as a self-contained learning resource connecting Python-level kernels down to synthesized logic, with measurable performance claims.

**Linked source:** The OpenTPU GitHub repository describes an open-source AI inference accelerator—including RTL, ISA, simulator, kernel compiler, and profiler—generated by AI agents and targeting a Xilinx Kintex-7 PCIe card (Inspur YPCB-00338). The project claims decode throughput ranging from ~4 tok/s for larger models (Phi-4-mini 3.8B int8) up to ~85.8 tok/s for smaller ones (LFM2.5-230M 4-bit), with DRAM utilization reaching 82–94% of the DDR3-1066 peak, and identifies remaining bottlenecks as DRAM efficiency and prefill rate limited by the four-column systolic matrix unit.

**HN discussion:** HN commenters engaged with the philosophical and engineering implications of AI designing its own inference hardware, including the prospect of a self-hosting feedback loop. One commenter framed the project as a potential milestone toward AI designing model architectures tuned for reconfigurable FPGA fabric.
