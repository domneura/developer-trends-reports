### [Sharing AI progress in mathematics](https://news.ycombinator.com/item?id=49984923)

- **HN engagement:** 957 points, 919 comments
- **Primary topic:** OpenAI releasing broad mathematical results produced by a frontier AI model, including proofs of major open problems
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://openai.com/index/sharing-ai-progress-in-mathematics/

AI systems autonomously resolving decades-old open mathematical problems raises immediate questions about proof verifiability, the role of formal verification tools like Lean, and how the field should establish trust in AI-generated mathematics. The release also signals a potential shift in what kinds of intellectual work AI can displace or accelerate.

**Linked source:** OpenAI's page announces a release of broad new mathematical results produced by an internal frontier model, published to a GitHub repository with Lean formalizations for computer-checkable proofs, compute usage estimates (averaging roughly three hours of ChatGPT Pro thinking per result), and reasoning summaries. The source states the release was informed by an Advisory Group on Mathematics and Artificial Intelligence at the Institute for Advanced Study, and that OpenAI plans to fund workshops and conferences around AI-produced mathematical results.

**HN discussion:** HN commenters reacted with a mix of awe, skepticism, and personal emotion, with several focusing on specific high-profile results such as the Unique Games Conjecture and Barnette's Conjecture, and one commenter independently reporting their own autonomous math researcher that solved a 12-year open problem in proof complexity. One commenter noted that LLMs appear to have made progress on four of the seven Millennium Prize problems, resolving one of them (Navier-Stokes), while others observed the results tend to be rigorous proofs of things the mathematical community already expected to be true.

### [Decisions API is in public beta](https://news.ycombinator.com/item?id=49984025)

- **HN engagement:** 314 points, 161 comments
- **Primary topic:** OpenAI Decisions API public beta for structured binary/categorical LLM judgments
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://developers.openai.com/api/docs/guides/decisions

The API offers a cheap, zero-output-token-cost path for routing, filtering, and classification tasks that previously required either prompt engineering with structured outputs or a separate fine-tuned model. The competitive landscape with Jev and Mercury Decide means developers now have multiple dedicated decision-inference options to evaluate on latency and calibration.

**Linked source:** The OpenAI Decisions API documentation describes an endpoint (`/v1/decisions`) that accepts structured 'questions' of type predicate, choice, or score, and returns probability distributions over answers rather than free-text output, priced at $0.10 per 1M input tokens with no output-token charges, currently available only on gpt-6-luna. The source notes it supports Zero Data Retention and HIPAA use for eligible customers, and recommends using labeled application examples to set routing thresholds based on false-positive/negative costs.

**HN discussion:** Commenters treat the Decisions API primarily as a competitive reaction to Jev and Mercury Decide rather than a novel OpenAI invention, with early benchmark results suggesting it is slower than Jev and produces less confident answers on ambiguous tasks. One commenter raised a philosophical concern that making decision probabilities explicitly visible could erode business confidence in AI-driven decisions.

### [Strands Decider 2B: a small, open-source, decision model](https://news.ycombinator.com/item?id=49987076)

- **HN engagement:** 195 points, 48 comments
- **Primary topic:** Strands Decider 2B: a small open-source decision model for structured agent decision-making
- **Evidence basis:** source-and-discussion
- **External page:** success
- **Source:** https://strandsagents.com/blog/introducing-strands-decider/

A purpose-built 2B decision model promises to gate agent tool calls at a fraction of the cost of a full LLM inference, but developers are already questioning whether the benchmark used to validate it is trustworthy and how to run it efficiently on consumer hardware.

**Linked source:** The Strands blog introduces Decider 2B, a small open-source model designed to answer structured binary (called 'noul') and choice questions cheaply inside agent pipelines, with the stated goal of sitting in intervention paths where a full LLM call would be too expensive. The source describes a Python-based integration pattern using an InterventionHandler with before_tool_call hooks that returns typed actions—Proceed, Deny, Confirm, or Guide—and notes the same handler shape works whether calling the decision model, a Cedar policy, or another agent.

**HN discussion:** Commenters engaged most with peripheral concerns: the suitability of JevBench as an evaluation standard, the hardware case for running micromodels on NPUs rather than CPUs, and confusion about the 'noul' naming convention for binary choices. Positive reception focused on the blog post's accessibility rather than the model's technical merits.
